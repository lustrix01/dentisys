# Implemented Features

What DentiSYS does today. Behaviour is defined by [spec.md](../spec.md); open and partial work is in the [product backlog](PRODUCT_BACKLOG.md).

- **implemented, tests passing**: the code exists and `scripts/check.ps1` and `scripts/check-postgres.ps1` ran tests covering it, and they passed.

## Accounts and sign-in

- First Dean/Admin account created by a controlled bootstrap script — REG-010 — implemented, tests passing.
- Password sign-in with optional authenticator-app 2FA and recovery codes — AUTH-005, AUTH-006 — implemented, tests passing.
- Password policy: 8–32 characters with the existing composition rules, shown in every set-password form; the show/hide control stays aligned to the input row — AUTH-005 — implemented, tests passing.
- A 401 on a non-auth request attempts one silent session refresh; the server remains authoritative for the 30-minute idle limit and the activity header only marks genuinely active requests — AUTH-007 — implemented, tests passing.
- Google Sign-In for existing accounts, linked only after password and 2FA confirmation, bound to a stable Google ID — AUTH-003, AUTH-010 — implemented, tests passing.
- Five-part structured names (Prefix, First, Middle, Last, Suffix) for every person and invitation, with Unicode-aware validation — ID-002 — implemented, tests passing.
- One canonical name source; a name change shows everywhere without rewriting business tables — ID-002 — implemented, tests passing.
- Dean, Faculty, Secretary and Student can change only their own five-part name from a shared profile dialog; authenticator-app MFA requires a fresh TOTP code, while recovery codes are rejected. Profiles reject identity-critical fields, and Faculty cannot rename an activated Student — ID-002 — implemented, tests passing.

## Attendance

- Attendance Monitoring offers only the Faculty's assigned courses, and only sections of the chosen course — ATT-001 — implemented, tests passing.
- The attendance worksheet header separates a read-only "Session status" panel (Live session + code + start time / Scheduled session / No session running / View only / Checking) from an actions row (Start session when idle; Schedule session while live; Sessions), keeping the hide-while-live rule — UI-005 — implemented in code.
- Start session, Schedule session and Edit session set times with a clock-style picker for all four times: a field you can type in plus a flyout of hour, minute and AM/PM wheels (ATT-001). Start session opens filled for the class's meeting happening now or next (a later date makes it Schedule session), using the class's grace periods (default Present +15 min, Late +30 min; saved on the class when Faculty use others, audited as "Class grace periods changed") and its saved face and geofence choices. Cutoffs, face, geofence, map and radius sit under a closed "More settings" with a one-line summary. Components: `TimePicker.tsx`, `SessionTimeFields.tsx`, `StartSessionModal.tsx`; database: migration 065.
- Faculty can turn on Sessions from the Weekly Schedule for a class (a section under the weekly meetings in the class Edit dialog; the choices save at once; ATT-008). DentiSYS then keeps one scheduled session for each weekly meeting in the next 7 days and adds more each day, up to the end of the term and never for an archived class. Each session opens 15 minutes before the meeting, uses the class's grace periods, face and geofence choices (geofence uses the meeting room's saved location and the class radius) and shows an Auto pill in Sessions. Faculty edit or revoke them like any scheduled session; a revoked or edited one is not created again, and a meeting that overlaps a session the class already has is skipped. Turning it on over another class's booking asks first (Turn on anyway) and notifies that Faculty; turning it off revokes sessions that have not opened; changing the weekly schedule first warns "This changes N upcoming sessions.".
- Every Secretary manual change (first mark, change, Excused) is a request the section's Faculty approves, with bulk approve, reject with a note and history. Approved records read "Secretary (approved by Faculty)". Requests close on a direct Faculty mark, a session revoke or a face check-in. Notices are in-app only — ATT-006 — implemented, tests passing.
- Every Secretary or Faculty override records actor, Student, class, session, old and new status, reason and time — ATT-006 — implemented, tests passing.
- Faculty Class Attendance Activity, a tab in Attendance Monitoring, shows their own and their Secretary's attendance changes with that full context — ATT-006 — implemented, tests passing.
- Dean Attendance Reports and the all-classes attendance export count every record, with no cap — ATT-001 — implemented in code.
- A session whose class end equals its opening time is refused with "Class end must be after the opening time."; the 12-hour limit stays — ATT-001 — implemented, tests passing.

## Superadmin and Dean

- The Superadmin is its own role and account, exactly one, non-teaching staff. The server script (backend/bin/account-admin.php) creates it with an emailed set-password link and changes its login email; on the first sign-in it must set up authenticator 2FA before any page opens (/2fa/setup) and cannot turn 2FA off. Its Profile works like the Dean's (name, password, 2FA, Google link) with a read-only email — SYS-001, ADM-001, AUTH-006 — implemented, tests passing.
- The Dean has Dashboard, Reports & Analytics, Faculty Invitations, My Activity (only the Dean's own actions), Profile and Settings. The Dean / Superadmin switch is gone; old /admin/terms, /admin/rooms, /admin/course-catalog and /admin/classes links lead to the Superadmin pages, which send anyone else to their own home — ADM-001, SEC-005 — implemented, tests passing.
- The Superadmin has Overview, People & Accounts, Classes, Course Catalog, Academic Terms, Rooms, Face Enrolment Flags, Audit Trail, Profile and Settings — ADM-001 — implemented, tests passing.
- Superadmin Overview: a Needs attention list (expired invitations, Faculty without classes this school year, accounts inactive 30+ days, next term without dates), each opening its page already filtered; graphs of accounts by status, weekly sign-ins (12 weeks), 2FA use, failed sign-ins (14 days), Students per year level and class sections per course; tiles for the current term, courses, rooms and open face enrolment flags; and the latest 10 audit events — ADM-001 — implemented, tests passing.
- Superadmin Audit Trail: an Activity / Class work switch; Class work lists grades, attendance and retention rows read-only with Faculty, class, Student, area and date filters and before/after values; the Activity view never shows them — ADM-001, SEC-005 — implemented, tests passing.
- Filters and sorting: Course Catalog filters by units (lecture only / has Laboratory) and use (used this school year / not used), and its columns sort from their labels. People & Accounts filters on the server by status (Active by default; Invited; Deactivated), course and, for Faculty, teaching this school year, or for Students year level, class section and Class Secretaries, plus one Needs attention filter (never signed in, inactive 30+ days, 2FA off, invitation expired); Name, Student No., Classes and Last Activity sort the whole list on the server, and the Excel export follows the filters and order. Tables across the app sort from their column labels (docs/frontend.md "Table sorting") — ADM-001, UI-001 — implemented, tests passing.
- Classes (Superadmin): every Faculty member's class sections, Active and Archived (all school years), with filters, the real roster and the Class Secretary, read-only. Change Faculty moves a current, active class to another active Faculty member with a reason: the class keeps its students, grades, attendance, sessions, Class Secretary and join code, its grade weights are copied to the new Faculty member (refused when they already have their own for that course and term), and it is refused while an attendance session is open. Both Faculty members get a notice and an email, the Class Secretary a notice, and the change is audited. Creating, editing, archiving and restoring stay with Faculty — CLS-003, ADM-001 — implemented, tests passing.
- Course Catalog (Superadmin): edit a course's code, title and lecture/laboratory units and retire or restore it. A retired course leaves Faculty's course list and cannot be typed again (Faculty are told to ask the Superadmin); existing classes keep it. Courses are never deleted — ADM-001 — implemented, tests passing.
- People & Accounts (Superadmin): Faculty (with their classes), the Dean (with a Dean badge, listed with the Faculty) and Students. Deactivate or reactivate a Faculty or Student account: deactivation ends every session and blocks every sign-in ("Contact the Superadmin."), keeps all records, and also blocks a Student's Class Secretary sign-in; a Faculty member with a class this school year cannot be deactivated, and the classes are listed; the Dean cannot be deactivated. Each row's Actions menu also offers Sign out everywhere, Reset 2FA (removes the authenticator and recovery codes, signs the person out and emails them) and, for enrolled Students, Revoke face enrollment; invited people show as Invited or Invitation expired with Resend and Revoke. People & Accounts and Course Catalog export to Excel — ADM-001 — implemented, tests passing.
- Account management (Superadmin People & Accounts): move a Faculty, Student or Dean account to a new email after checking the person's university ID in person (the old address is retired for good, every session ends, the password, 2FA and Google link are removed, and a set-password link goes to the new address only) and correct a name, both with a reason. Hand Over Dean Role makes an active Faculty member the Dean; the outgoing Dean stays as Faculty or is deactivated; refused while a term is in progress or while the new Dean has a class whose term has not ended; both are signed out and emailed. The server script moves the Superadmin's own email, resets its 2FA after a lockout and un-retires an address — ADM-001 — implemented, tests passing.

## Deliberate boundaries

- Email-code sign-in verification is retired; system email remains for non-authentication features.
- Facial biometrics are not a complete production flow (BIO-001 to BIO-010).
- The demo and production VPS servers (RUN-002, DEL-001; see [vps-deployment.md](vps-deployment.md) and [release-guide.md](release-guide.md)) use manual GHCR publishing, Traefik HTTPS, app-only Watchtower updates and PostgreSQL backups; CI/CD remains out of scope.

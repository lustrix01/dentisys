## Accounts and sign-in

- First Dean/Admin account created by a controlled bootstrap script — REG-010 — implemented, tests passing.
- Password sign-in with optional authenticator-app 2FA and recovery codes — AUTH-005, AUTH-006 — implemented, tests passing.
- Remember this device: an unchecked "Remember this device for 30 days" box on the 2FA code step (not on the recovery-code step, not during the Superadmin's first 2FA setup). Ticked, that browser keeps an HttpOnly `trusted_device` cookie (SameSite=Lax, `Path=/api/auth`, Secure on HTTPS; only its SHA-256 is stored in `mfa_trusted_devices`) and skips the code at password or Google sign-in for 30 days from that moment, never extended; one browser remembers one account. It stops working on password change or reset, 2FA reset, 2FA turned off or on, recovery-code regeneration, sign-out everywhere, deactivation, an email move, a Dean handover, and Profile's "Forget my trusted devices" (`POST /api/auth/mfa/trusted-devices/forget`; the count comes from `GET /api/auth/mfa/settings`). Audit: `trusted_device_remembered`, `trusted_devices_forgotten`, and the sign-in row says "2FA skipped on a remembered device" — AUTH-006 — implemented, tests passing.
- Password policy: 8–32 characters with the existing composition rules, shown in every set-password form; the show/hide control stays aligned to the input row — AUTH-005 — implemented, tests passing.
- Superadmin sign-in page (12.8): the Superadmin signs in only at `/superadmin/sign-in` (linked from nowhere, `noindex`): the `/login` page with the heading "Superadmin Sign In" and no Remember me box. The shared `/login` refuses the Superadmin and the Superadmin page refuses every other role: password sign-in answers 401 "Invalid credentials." like a wrong password (counted toward the per-email lock), Google answers 404 like an unknown account, and both audit "wrong sign-in page". The request says which page it came from (`sign_in_page: "superadmin"`; missing = `/login`). After activation or a password reset the Superadmin is sent to its page (`sign_in_path` in the response); in a Superadmin tab, sign-out, the idle sign-out and the 2FA Back buttons return there, and Forgot password's Back link too (`?from=superadmin`).
- Remember me: an unchecked "Remember me for 7 days" box on the sign-in page, beside "Forgot password?" (password and Google; the choice rides through the 2FA step and the Google link step). Unticked, the session keeps the 30-minute idle limit and the refresh cookie is a browser-session cookie (no Max-Age). Ticked, the session has no idle limit and the cookie keeps a Max-Age equal to the time left until the session's fixed 7-day end, never extended by use. The Superadmin is never remembered (the server stores off without an error). Every action that ends sessions still ends a remembered one. Sent as optional boolean `remember` on `POST /api/auth/login` and `POST /api/auth/google` (400 if not a boolean); stored in `auth_sessions.remembered`; `GET /api/auth/me` returns `remembered`. Sign-in audit rows end with "Remember me: on." or "Remember me: off." — AUTH-007 — implemented, tests passing.
- A 401 on a non-auth request attempts one silent session refresh; the server remains authoritative for the 30-minute idle limit and the activity header only marks genuinely active requests — AUTH-007 — implemented, tests passing.
- Google Sign-In for existing accounts, linked only after password and 2FA confirmation, bound to a stable Google ID — AUTH-003, AUTH-010 — implemented, tests passing.
- Five-part structured names (Prefix, First, Middle, Last, Suffix) for every person and invitation, with Unicode-aware validation — ID-002 — implemented, tests passing.
- One canonical name source; a name change shows everywhere without rewriting business tables — ID-002 — implemented, tests passing.
- Dean, Faculty, Secretary and Student can change only their own five-part name from a shared profile dialog; authenticator-app MFA requires a fresh TOTP code, while recovery codes are rejected. Profiles reject identity-critical fields, and Faculty cannot rename an activated Student — ID-002 — implemented, tests passing.
- A signed-out visitor who opens a class join link sees on the sign-in page that they must sign in to join the class, and that a Student without an account must first accept their Faculty's invitation email; after sign-in the Join a class dialog opens with the code filled in — CLS-004, backlog 14.8.

## Grading and retention

- Faculty edit grading categories and weights; weights must total exactly 100% and grades stay computed — GRD-002, GRD-003 — implemented, tests passing.
- Grade submission and release gates: Faculty submit a class's grades with Submit grades in the Grade Computation class picker; the confirmation lists students with missing scores and students entering Remedial or Irregular reenrollment, and submitting is refused while an attendance session is open. Each class card shows Not submitted, Midterm published, Late, Submitted, Submitted late, Grade change draft or Awaiting Dean approval. Each term has a submission deadline (Superadmin Academic Terms "Grade Deadline"; empty = end date + 14 days). Secretary attendance requests on a submitted class are refused, and join requests to it too. ## Deliberate boundaries

- Email-code sign-in verification is retired; system email remains for non-authentication features.
- Facial biometrics are not a complete production flow (BIO-001 to BIO-010).
- The demo and production VPS servers (RUN-002, DEL-001; see [vps-deployment.md](vps-deployment.md) and [release-guide.md](release-guide.md)) use manual GHCR publishing, Traefik HTTPS, app-only Watchtower updates and PostgreSQL backups; CI/CD remains out of scope.
